# Native network-filter adapter

This Swift package compiles VIGIL's bounded network decision state against the public macOS
Network Extension SDK. It contains a real `NEFilterDataProvider` subclass and an entitlement-free
XCTest suite, but it is not an activatable System Extension bundle.

The provider projects the complete kernel audit token, socket protocol, native hostname, numeric
remote endpoint, direction, and callback time into the compact policy state. It performs no DNS,
file, database, XPC, UI, model, or logging work in `handleNewFlow`. Managed flows fail closed when
metadata, clock, signature lease, pinned resolution, or budget is unavailable; unattributed host
traffic remains unaffected.

Policy envelopes are domain-separated Ed25519 signatures over the exact Rust-produced payload.
The verifier authenticates the envelope before decoding the strict payload, binds it to an
expected installation instance, enforces issuance/expiry, and only then permits atomic monotonic
installation. The committed fixture is generated by `vigil-network` and checked in both languages.

The package requires macOS 15 because the current public SDK exposes `remoteFlowEndpoint` there;
the older endpoint property is unavailable to Swift in this SDK. The same SDK marks
`NEFilterControlProvider` unavailable on macOS, so policy distribution must be out-of-band through
a protected containing-app/shared-container mechanism. No fictitious macOS control provider is
modeled.

Run the adapter's test suite with:

```console
make test-macos-network-adapter
```

`Tests/VigilNetworkAdapterTests` covers envelope authentication (`SignedNetworkPolicyTests` —
domain separation, tampering, expiry, generation rollback) and flow authority
(`NetworkFlowDecisionTests` — pinned destinations, resolution mismatch, private and loopback
addresses, unmanaged-process isolation, expired policy). XCTest ships with Xcode rather than the
Command Line Tools, so a CLT-only machine can `swift build` this package but not test it.

`Configuration/` contains reviewed templates for a future Xcode System Extension target. They do
not grant an entitlement, sign a bundle, install a filter, or activate anything. Those steps still
require full Xcode, a Developer ID provisioning profile with Network Extension capability, a
containing application, notarization, and privileged-device tests.
