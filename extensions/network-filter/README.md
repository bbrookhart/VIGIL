# Native network-filter adapter

This Swift package compiles VIGIL's bounded network decision state against the public macOS
Network Extension SDK. It contains a real `NEFilterDataProvider` subclass and an entitlement-free
XCTest suite. `platform/macos/VigilMac.xcodeproj` now packages it inside a reviewable containing
application and unsigned System Extension; that product is not activatable without provisioning.

The provider projects the complete kernel audit token, socket protocol, native hostname, numeric
remote endpoint, direction, and callback time into the compact policy state. It performs no DNS,
file, database, XPC, UI, model, or logging work in `handleNewFlow`. Managed flows fail closed when
metadata, clock, signature lease, pinned resolution, or budget is unavailable; unattributed host
traffic remains unaffected.

Policy envelopes are domain-separated Ed25519 signatures over the exact Rust-produced payload.
The verifier authenticates the envelope before decoding the strict payload, binds it to an
expected installation instance, enforces issuance/expiry, and only then permits atomic monotonic
installation. The trusted write-side publisher holds one cross-process transaction lock while it
atomically publishes the exact signed envelope and durably records `(generation, envelope
digest)`. The provider side is read-only: startup double-reads that record around the envelope,
requires an exact match, and only then activates it. This permits restart recovery of exactly the
committed envelope without accepting another policy at the same generation. The committed fixture
is generated by `vigil-network` and checked in both languages.

The package requires macOS 15 because the current public SDK exposes `remoteFlowEndpoint` there;
the older endpoint property is unavailable to Swift in this SDK. The same SDK marks
`NEFilterControlProvider` unavailable on macOS, so policy distribution must be out-of-band through
the protected shared-container mechanism implemented here. `startFilter` now strictly parses the
factory-produced vendor configuration, resolves the App Group, and loads the durable policy before
reporting readiness; `stopFilter` clears the loader. The containing-app target links the same
configuration factory, while provisioning the real group and activation remain release work. No
fictitious macOS control provider is modeled.

The containing-app side also compiles a bounded `NEFilterManager` preference controller. It loads
before mutation, saves and reloads, verifies the exact configuration, reports drift separately,
serializes concurrent callers, and invalidates itself after an outcome-unknown timeout. Its
`enabled` result means only that the expected preference round-tripped; it never claims that an
extension is installed, activated, or enforcing traffic.

Run the adapter's test suite with:

```console
make test-macos-network-adapter
```

`Tests/VigilNetworkAdapterTests` covers envelope authentication (`SignedNetworkPolicyTests` —
domain separation, tampering, expiry, generation rollback) and flow authority
(`NetworkFlowDecisionTests` — pinned destinations, resolution mismatch, private and loopback
addresses, unmanaged-process isolation, expired policy), durable publisher/reader behavior,
provider lifecycle/configuration, and containing-app preference failure/drift/deadline behavior.
XCTest ships with Xcode rather than the
Command Line Tools, so a CLT-only machine can `swift build` this package but not test it.

`Configuration/` contains the reviewed plist and entitlement inputs consumed by the Xcode target.
`make build-macos-app` compiles the unsigned `.app`, embeds the `.systemextension` in
`Contents/Library/SystemExtensions`, and validates both products. This does not grant an
entitlement, sign, install, or activate anything. Those steps still require a Developer ID
provisioning profile with Network Extension capability, notarization, and privileged-device tests.
