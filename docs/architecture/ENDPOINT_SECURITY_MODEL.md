# Endpoint Security enforcement model

**Status:** Phase 3 foundation; native adapter compiled, entitlement-dependent activation untested

## Verified Apple surface

Development on 2026-08-30 used Apple Silicon macOS 26.6.2, Command Line Tools macOS SDK 26.5,
and Swift 6.3.3. The installed public headers and Swift module verify:

- `es_new_client` and `es_subscribe`;
- `ES_EVENT_TYPE_AUTH_EXEC`, `ES_EVENT_TYPE_AUTH_OPEN`, `ES_EVENT_TYPE_AUTH_CREATE`,
  `ES_EVENT_TYPE_AUTH_RENAME`, `ES_EVENT_TYPE_AUTH_UNLINK`, `ES_EVENT_TYPE_NOTIFY_FORK`, and
  `ES_EVENT_TYPE_NOTIFY_EXIT`;
- `es_respond_flags_result` is required for `AUTH_OPEN`, while other authorization events use
  `es_respond_auth_result`;
- every auth message carries its own Mach deadline, and a client that misses it may be killed;
- per-type sequence numbers require message version 2 and global sequence numbers require version
  4; gaps indicate dropped kernel events;
- the process `(pid, pidversion)` identity changes across exec and is represented by the audit
  token; caller-supplied PID is therefore never the attribution key.

The Swift adapter compiles with a macOS 13 deployment target, uses only public APIs, returns no ES
pointer outside the callback, disables decision caching, and independently denies once its 5 ms
deadline safety margin is reached. Create and rename projection handles both SDK destination
forms: an existing file or a directory plus new filename.

## Portable fast path

`vigil-endpoint` is the entitlement-free deterministic contract. A compact `FastPathState` holds:

```text
audit token → managed session
managed session → workspace roots + exact executable allowlist
global protected path prefixes
deadline safety margin
```

Policy state is validated and bounded before it reaches authorization. Evaluation performs only
bounded in-memory map/set lookups and component-aware path comparisons. It does not canonicalize
through the filesystem, read SQLite, call a daemon, log, allocate unbounded data, perform network
I/O, show UI, or invoke a model.

Managed authorization semantics are conservative:

- `AUTH_EXEC`: exact executable path allowlist; target audit-token attribution replaces the
  pre-exec identity only after allow;
- `AUTH_OPEN`: complete normalized path inside a workspace, protected-prefix denial, known access
  flags, and an exact flags response;
- `AUTH_CREATE`, `AUTH_RENAME`, and `AUTH_UNLINK`: every affected path must remain inside a
  workspace and outside protected prefixes;
- `NOTIFY_FORK`: child audit token inherits session attribution;
- `NOTIFY_EXIT`: attribution is removed;
- missing deadlines, truncated paths, malformed paths/tokens, and expired safety margin deny for
  managed processes;
- untracked processes allow rather than turning an attribution defect into a host-wide outage.

The last property makes trusted root binding and loss-of-attribution telemetry release-critical.
The native adapter now subscribes to all seven modeled event kinds. Its
`NativeFastPathPolicyState` validates bounded, monotonically versioned snapshots before install,
uses full audit tokens for attribution, moves identity after an allowed exec, inherits it on fork,
removes it on exit, and purges mappings when a new snapshot removes their session. The Swift check
exercises protected, malformed, truncated, similar-prefix, rename-escape, executable, unmanaged,
snapshot-replay, fork, exec, and exit cases without requiring the ES entitlement.

The real callback shares a fixed-size `NativeAuthorizationMetrics` accumulator with authenticated
control health. It records verdicts, malformed and deadline-guard denials, late or failed ES
responses, global/per-type sequence anomalies, maximum latency, and minimum deadline headroom
without callback logging or I/O. A second deadline check after policy evaluation converts a result
to denial if evaluation consumed the safety margin. Metrics reset with the process and never grant
authority; see ADR 0023.

## Signed policy installation

Rust serializes compact state as canonical JSON inside a bounded Ed25519 envelope. The payload is
bound to a schema version, extension instance, monotonic generation, issue time, and expiry. Swift
accepts public keys only from configuration, verifies the signature and signing domain before
decoding policy JSON, rejects unknown fields, then reuses the fast-path installation validator.
Generation rollback is rejected during state installation and across restart by a durable
high-water mark committed before policy activation. Corrupt persistence fails startup rather than
resetting the generation. The shared fixture is generated by Rust, consumed by Swift, and pinned by
both CI implementations. See the
[transport contract](ENDPOINT_POLICY_TRANSPORT.md).

## Simulator and health

`SimulatedEndpointSecuritySource` replays auth/notify events, processing delays, explicit drops,
source failure, per-type sequence fields, and global sequence gaps. Metrics expose authorization
count, allows, denials, deadline-guard denials, already-late events, dropped events, and maximum
authorization latency. Source failure is an error, never a clean end of stream.

The verified snapshot expiry remains in native policy state. At the exclusive expiry boundary,
managed authorization and new root attribution fail closed and control health becomes unready.
A wall-clock read failure has the same managed-process posture. Untracked processes still allow,
preventing an extension or daemon outage from becoming a denial of service for the whole host.

Native root registration is a strict authenticated control operation, not a PID lookup. It binds
the full audit token to a session in the currently installed generation, is idempotent for an exact
replay, and refuses token reassignment, stale generations, malformed tokens, unknown sessions, and
expired policy. A signed daemon and trusted mechanism for obtaining the launched root's audit token
are still required before this path can be exercised across processes.

Listener peers are capped at 64 and carry bounded refreshable idle timers. Only a message that
passes the audit-token-derived code requirement refreshes its timer. Wrong-identity peers receive a
fixed rejection and are disconnected immediately; malformed, idle, disconnected, and shutdown
paths all cancel their timer resource.

## Remaining release boundary

This is not installed OS enforcement. The environment lacks full Xcode, so the repository does
not invent an `.xcodeproj`, extension-point plist, containing-app activation flow, or packaging
result. The signed envelope authenticates policy bytes but is not itself a daemon transport,
Keychain-backed production key, or durable IPC replay store. The adapter has a bounded listener,
strict control message bridge, and audit-token-derived sender verification. A real anonymous XPC
request proves the successful same-binary peer path, while a bounded client owns request deadlines
and treats timeout outcomes as unknown. There is no registered Mach service or
signed `vigild` peer to exercise successfully. Apple must
approve `com.apple.developer.endpoint-security.client`; users must grant Full Disk Access; and an
entitled build must pass signing, notarization, activation/upgrade, deadline, drop,
cache-invalidation, and prohibited-operation tests on disposable Macs before Phase 3 exit criteria
can be claimed.
